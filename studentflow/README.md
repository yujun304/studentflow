# StudentFlow

StudentFlow는 중학교 학생회와 담당 선생님이 공지, 업무, 제출물, 조 편성, 회의 기록을 관리하는 반응형 운영 화면입니다. FastAPI 백엔드와 실제 학생 계정에 연결되며 변경 내용은 PostgreSQL에 저장됩니다.

## 실행 방법

| 목적 | 명령 |
| --- | --- |
| 개발 서버 실행 | `pnpm dev` |
| 타입 검사 | `pnpm check` |
| 배포용 빌드 | `pnpm build` |

프로젝트 루트(`/home/ubuntu/studentflow`)에서 명령을 실행합니다. Vite가 출력하는 로컬 주소를 브라우저에서 열면 됩니다. 로그인 없이 특정 화면의 레이아웃만 검토하려면 주소 뒤에 `?demo=1`을 붙일 수 있습니다. 역할별 화면도 확인하려면 `?demo=1&role=TEACHER`처럼 역할을 지정할 수 있습니다. 일반 사용 흐름에서는 로그인 화면을 이용하세요.

## 기술 구성

| 항목 | 구현 |
| --- | --- |
| 프레임워크 | React 19 + Vite + TypeScript |
| 문서 구조 | Vite MPA + 페이지별 HTML 진입점 + 일반 문서 링크 |
| 스타일 | Tailwind CSS 4 + CSS 디자인 토큰 |
| 아이콘 | Lucide React |
| 상태 | React Context 기반 브라우저 메모리 상태 |
| 최소 화면 | 360px, 가로 스크롤 없는 모바일 우선 구조 |

## 화면과 체험 흐름

| 화면 | 주요 행동 |
| --- | --- |
| 로그인 | 역할을 선택해 임원·부장·회장단·담당 선생님 화면을 즉시 체험 |
| 대시보드 | 역할별로 오늘 처리할 업무와 검토 대기 항목을 우선 확인 |
| 업무·업무 상세 | 칸반 또는 모바일 상태 탭에서 업무 확인, 수정, 파일 제출 |
| 제출 및 검토 | 파일 정보 확인 후 승인 또는 구체적 사유를 포함한 반려 |
| 공지 | 중요 공지 확인, 대상 선택·미리보기·게시 흐름 |
| 캘린더 | 월간 날짜 셀에서 업무 마감·공지를 함께 훑고, 날짜 선택·목록 전환으로 세부 일정 확인 |
| 조 편성 | 조 구성원 확인, 중복 배정 없이 조 이동 |
| 회의록 | 회의 결정 내용과 첨부 파일 기록 |
| 알림 | 읽지 않은 알림을 확인하고 관련 화면으로 이동 |
| 사용자 및 권한 | 담당 선생님 역할에서 사용자 역할 변경 |
| 기수 아카이브 | 지난 기수의 읽기 전용 기록 및 로딩·오류·빈 상태 보기 |

## 역할 미리보기

로그인 화면에서 역할을 고르거나, 로그인 후 데스크톱 상단 및 모바일 메뉴의 **역할 미리보기**에서 전환할 수 있습니다.

| 역할 | 기본 우선 정보 | 주요 권한 |
| --- | --- | --- |
| `MEMBER` | 내 업무와 공지 | 본인 업무 제출 |
| `DEPARTMENT_HEAD` | 소속 부서 진행 상황, 제출 검토 | 업무 생성·수정, 제출물 검토, 조 편성 |
| `EXECUTIVE_BOARD` | 전체 업무와 공지 | 공지 게시, 조 편성 |
| `TEACHER` | 승인 대기와 사용자 관리 | 최종 검토, 역할 변경 |

권한이 없는 화면을 단순히 숨기지 않고, 해당 기능을 실행할 수 없는 이유와 가능한 범위를 안내합니다.

## 코드 구조

```text
client/
├── {login,tasks,...}/     # 메뉴별 HTML 문서 진입점
├── tasks/detail.html      # 동적 업무 상세 문서 진입점
├── announcements/detail.html
├── events/detail.html
└── src/
├── components/
│   ├── AppShell.tsx       # 공통 사이드바·상단바·모바일 메뉴
│   ├── MpaLink.tsx        # 클릭을 가로채지 않는 문서 링크
│   └── primitives.tsx     # 버튼·입력·배지·모달·상태 컴포넌트
├── contexts/
│   └── AppContext.tsx     # 데모 상태와 사용자 행동
├── lib/
│   ├── api.ts             # 실제 API 연결 시 교체할 단일 경계
│   └── sample-data.ts     # 한국 학교 맥락의 샘플 데이터
├── pages/                 # 화면별 React 컴포넌트
├── types.ts               # 도메인 타입
├── App.tsx                # 현재 문서 경로에 맞는 화면과 로그인 보호 처리
└── index.css              # 색상·테두리·반응형·접근성 토큰
```

## 실제 API 연결

`client/src/lib/api.ts`가 HttpOnly JWT 쿠키와 CSRF 토큰을 사용하는 `/api/v1` API에 연결됩니다. `AppContext.tsx`는 로그인 후 현재 사용자의 권한 범위에 맞는 사용자·업무·공지·제출·조·알림 데이터를 불러오고 변경 후 다시 동기화합니다.

## 상태 구현 범위

공통 UI에 `LoadingState`, `EmptyState`, `ErrorState`, `PermissionState`, `SaveMessage`를 제공합니다. 업무 제출, 검토 승인·반려, 공지 게시, 조 이동, 역할 변경은 API 응답 후 서버 데이터와 다시 동기화됩니다.

더 자세한 UX 이유는 [화면별 UX 결정 문서](docs/ux-decisions.md)를 참조하세요.
